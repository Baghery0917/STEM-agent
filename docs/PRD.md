# 1. 项目概述

STEM Educational Agent是一个面向学生的智能物理教学系统，核心能力是根据多模态输入得到学生历史学习画像（知识点掌握度、答题正确率、情绪状态等），为每位学生提供个性化的题目讲解以及个性化练习。系统通过对接外部教学模块、练习模块和情绪识别模块，结合大语言模型（LLM）完成教学交互。

## 1.1 当前范围

- 用户角色：学生（教师、管理员角色暂不纳入）
- 交互模式：教学模式、练习模式

# 3. 功能需求

## 3.1 知识结构管理

### 3.1.1 数据结构 

知识体系采用三级层次结构：

篇（Volume）
└── 章（Chapter）
    └── 节（Section）

每个节是系统中最细粒度的知识单元，题目、掌握度等均关联到节级别。一个知识点关联到某个节。

### 3.1.2 功能列表 

| 功能 | 说明 |
|------|------|
| 导入知识结构 | 支持通过 JSON 文件批量导入篇/章/节 |
| 可视化管理 | 前端提供树形界面，支持对各层级节点的增删改查 |
| 层级调整 | 支持节点的移动（如将某节从一章移至另一章） |
| 知识点详情 | 每个节包含名称、描述、所属层级路径 |

### 3.1.3 导入格式（JSON 示例）

{
  "volumes": [
    {
      "name": "力学",
      "chapters": [
        {
          "name": "运动学",
          "sections": [
            {
              "name": "匀变速直线运动",
              "description": "..." 
            }
          ]
        }
      ]
    }
  ]
}

### 3.1.4 kp model
知识点的模型
字段	说明
kp_id	唯一标识（六位数字，第一篇第二章第三节为 010203）
name	知识点名字（例如：匀变速直线运动）
description	关于这个知识点的简要描述
create_time	导入时间

## 3.2 题库管理

### 3.2.1 题目类型 1

- 选择题（单选 / 多选）
- 填空题

### 3.2.2 题目导入流程 

1. 用户提供 JSON 格式的原始题目文件（包含题目内容、最终答案、答案解析）
2. 系统调用 LLM 分析题目内容和答案解析（如有），自动提取关联的节（匹配到已有知识点树）
3. 系统只对题目的纯文本内容生成向量 embedding，存入 pgvector
4. 导入结果记录（成功 / 失败 / 知识点匹配情况）供人工审核


### 3.2.3 exercise model
题目数据模型（概要）

字段	说明
question_id	唯一标识
kp_id	关联 kp model
type	题目类型（single choice / multiple choice / fill）
question	题目（图片格式）
explanation	答案解析（图片格式）
answer	标准答案（要么是选项 ABCD，要么是一个数字）
item	题目+答案+答案解析（图片格式）
question_str	题目的纯文字部分
question_embedding	题目的纯文字部分的向量（存于 pgvector）
knowledge_points	关联知识点列表（多对多）
source	来源标记
create_time	导入时间
difficulty	难度，1-3

## 3.4 教学交互模块

这是系统的核心模块，描述学生提交题目后的完整处理流程。

### 3.4.1 会话定义

- 一次会话（Session）对应学生对一道题目的学习过程
- 会话内支持多轮对话（学生可就该题目持续追问）
- 会话由学生主动结束

### 3.4.2 教学交互主流程

学生提交题目（文本）
     │
     ▼
[1] 知识点分析
    调用 LLM 分析题目，识别涉及的知识点列表
     │
     ▼
[2] 学生数据检索
    查询该学生在相关知识点上的聚合统计数据：
    - 历史累计学习总时长
    - 历史错误率
    - 历史错误原因合集
    - 累计练题数量
    - 最后学习时间间隔
    查询该学生在相关知识点上的情绪统计数据：
    - 历史情绪图谱
     │
     ▼
[3] 教学策略获取
    将所属知识点列表 + 学生聚合统计数据
    发送至教学策略模块（HTTP API），获得教学策略
     │
     ▼
[4] 相似题目检索
    基于question_embedding + 知识点过滤，检索知识库的题目（如有）作为参考资料
     │
     ▼
[5] Prompt 组装
    将以下内容组装为 LLM Prompt：
    - 检索出的原始题（item）（图片格式）（如有）
    - 教学策略（指导讲解方式）
    - 用户问题
    - 该session的历史对话记录（多轮上下文）
    - 历史情绪图谱
     │
     ▼
[6] LLM 调用
    调用 OpenAI 兼容接口，获取讲解内容，返回给学生
     │
     ▼
[多轮] 学生追问 → 重复步骤 [3][5][6]
     │
     ▼
学生主动结束会话
     │
     ▼
[7] 会话后处理
    - 保存会话摘要
    - 情绪采集
    调用情绪识别模块（传入摄像头画面），获取该session的情绪分类
    - 更新学生知识点档案

### 3.4.3 情绪采集时机 

- 每个session结束后采集一次（学生发送最后一次消息时触发）
- 情绪值由外部情绪识别模块返回，格式为分类值（如：
  1. Confident – assured, self-reliant, optimistic
  2. Slightly uncertain – mildly doubtful, hesitant, questioning
  3. Discouraged – disappointed, losing motivation, feeling challenged
  4. Frustrated – annoyed, blocked, struggling to make progress
  5. Very frustrated – defeated, overwhelmed, feeling helpless）
- 进入档案的Emotion value为verbal情绪和facial情绪的加权值。

### 3.5.3 情绪采集时间 
完成一道题之后，从情绪模块获取这道题所属的[start_time,end_time]的facial emotion，写进practice_single_record表的emotion字段。
### 3.5.4 练习开始时的出题流程：
出题的业务逻辑由memory模块中的pgvector部分负责的
1. 用户练习前会直接传来的参数（提供筛选依据）：
- 当前学习进度：标识学生当前所处的最小颗粒度的知识体系位置（如：第三篇第二章第一节）。
- 目标难度等级：用户即时选择的难度范围（支持多选：Level 1, 2, 3）。
- 练习模式：指定为 General或 Focused。
- 目标知识点 (KP ID)：用户当前选择练习的核心知识点（支持多选，比如同时选择第三篇第一章第一节和第二节）。
2. 记忆模块数据检索 (Context Retrieval)： 
记忆模块接收请求后，根据参数进行过滤，抽出合适题目，提供给练习模块。
3. 练习模块和记忆模块交互逻辑：
- General 模式：
  - 抽题规模：单次仅从题库中检索并返回 1 道 符合条件的题目。
  - 数据下发：下发题目的所有信息至练习交互模块。
- Focused 模式：
  - 抽题规模：批量检索符合条件的题目，上限为 20 道。若题库可用题量不足 20 道，则采取“全量提取”策略。
  - 数据下发：下发题目的所有信息及本次实际成功提取的题目总数至练习模块。
### 3.5.5 练习完成后处理流程
练习记录的业务逻辑由memory模块中的PostgreSQL部分负责的
1. 数据获取机制： 记忆模块通过 MemoryManager 统一入口实时监听/接收作答反馈。每当用户完成一次交互（如提交答案），系统立即触发对应接口。
2. 记录分流与档案隔离逻辑：
- 所有作答均写入practice_session_record和practice_single_record流水表（含题目 ID、答案、耗时、情绪、是否跳过等）。
- 正常作答：联动更新学生档案（mastery model、emotion model）。
- Skip（仅 General 模式）：答案中若用户回答“skip”，对于该题，practice_single_record流水表的result标记为skip，那么该题信息不用于更新档案（不计入学生的所有持久化模型）。

3.9 学生报告模块
3.9.1 功能概述
根据用户选择的模式（recent 或 all），从数据库中分流提取不同时间维度的知识点统计数据及情绪记录，用于支撑前端“动态周报”或“学习全景”的展示。
3.9.2 模式定义与逻辑详述
模式 A：Recent 模式（近一周动态）
该模式旨在展示用户近期的活跃状态，侧重于增量变化。
- 维度一：活跃知识点统计 (Active Knowledge Points)
  - 判定标准：筛选 $t_{current} - 7 \le t_{active} \le t_{current}$ 范围内的记录。
  - 逻辑：通过双维度时间戳 last_practice_time（最后练习时间）或 last_teaching_time（最后听课时间）进行判定。
  - 输出内容：凡命中上述条件的知识点，提取其全量统计指标（包含该知识点下属的累计数据）。
- 维度二：近期情绪明细 (Recent Emotion Logs)
  - 筛选标准：end_time 在最近 7 天内。
  - 输出内容：返回情绪记录的明细列表（无需按知识点聚合，按时间倒序排列）。
模式 B：All 模式（全量知识图谱）
该模式旨在展示用户学习路径的全量沉淀。
- 维度一：全量知识点聚合 (Mastery Aggregation)
  - 筛选标准：learned_flag = True（已进入学习状态的知识点）。
  - 逻辑：取消时间滤网，从 mastery model 中拉取所有已学知识点。
  - 输出内容：知识点 ID、掌握度、正确率、总题量、教学次数等聚合数据。
- 维度二：全量情绪趋势 (Historical Emotion Trends)
  - 处理逻辑：基于 emotion model 数据库，以 kp_id 为维度进行分组聚合。
  - 输出内容：每个 kp_id 对应一个 emotion_value 列表，列表内数据按 timestamp 升序排列，用以还原学生在该知识点上的心理变化轨迹。
